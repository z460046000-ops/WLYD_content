# 生成提速方案：减少模型往返，先交初稿

日期：2026-10-16。状态：用户已确认前四项，源码0.9.0已实施，未安装/重启DSH。下文保留0.8.0问题分析及设计依据；没有本轮真实测速结果，不承诺固定分钟数或提速比例。

## 这次解决的问题

0.8.0快速分支仍是：每章知识库查询→长证据逐批LLM提取→LLM写章→全部章结束→多组LLM复核→workflow写report。draft虽然取消自动修复，但事实提取有串行批次，复核仍占用用户等初稿的时间。规划也至少包含宏观事实提取与大纲两层模型调用。主要优化方向是减少调用层数，而非仅缩短规则文字。

只读抽查两个已知产物目录，没有找到标明qualityMode=draft的新版运行；不能把其中旧/严格链路记录当成用户最新0.8.0耗时。旧样本13e65b20-482a-49e4-919b-4b85c09b7ba2有149次模型调用，其中83次复核；43次检索服务累计约45.9秒，模型服务和排队时间多请求重叠，不能相加当墙钟。该样本只支持优先检查模型往返，不证明本次检索一定快。

## 保留的要求

- 从当前授权项目知识库实际取材；逐章查询与命中可核对，规划锚点不冒充新命中。
- 粗大纲与少量能力→场景→问题→趋势主线先展示，由用户确认版本后再生成。
- 引用有真实来源，未验证/推演明确标注；案例和企业背书缺材料给待补卡，不编造。
- 前后关联检查仍为必经工作；初稿先交付时明确显示复核中，不能说检查已通过。
- 保留章节隔离、评论/修改/版本和strict旧链路，不把所有材料重新喂给一次全文调用。

## 六步实施与验证

| 步骤 | 改动 | 验证 |
|---|---|---|
| 1. 取得当前计时基线 | 核对真实run的runtime/quality、章节数、查询、模型调用和排队/执行时间，区分正文可读与复核结束 | 使用已有最新运行，不为补表整篇重跑；拿不到0.8.0运行时标为待测 |
| 2. 合并宏观提取和规划 | 少量真实知识片段一次输出粗目录和主线；程序核对来源，保留plan/SHA/确认 | 未命中不创建规划、未确认不可生成；目录与来源可追溯。规划常见串行模型层数由2降为1 |
| 3. 合并章内提取与写作，收敛查询 | 主查询一条，零命中/不足再补一条；原文按可定位段落编号，模型同次完成归纳、用途/边界和写作，程序补引用，保存兼容cards/extraction。长章按需拆而非硬塞一次 | 每章实际查库；相同输入对比模型调用数与输入规模；无伪造引用，已有改单章工具仍可用；选用原文完整归档，首稿选材不足可扩写 |
| 4. 正文先交付，复核后台执行 | 每章写完刷新初稿；全篇正文可读后不再等待语义复核。复核走宿主作业，标记版本与状态，失败保留正文/审核项 | 记录首次正文、完整初稿、复核完成三个时间；进程退出可追踪；用户改章后旧复核结果不能覆盖新稿，也不得标新稿已通过 |
| 5. 复用来源卡与查询结果 | 项目/用户/授权库/文档版本或内容哈希/规则与提示词组成缓存键；先核授权再复用，不重复概括相同片段 | 撤权、文档/规则变化使缓存失效；后台未提供可靠文档版本时只做保守缓存，不声称跨版本一致 |
| 6. 最小回归与交付 | 保留strict；核对确认、来源、版本、取消/恢复、局部修改，验证后打包；本轮不安装或重启 | 离线验证调用层数和长材料/中断边界；真实CallWan计时待用户指定切换后测试，不做低价值并发穷举 |

影响：planning/retrieval、draft-generation/fact-cards/facts、workflow/tasks/review、chapters、相关测试和文档。缓存是后续可独立落地的项；首批优先步骤2、3、4。

## 容易出错

1. 原文编号有效不表示概括语义正确；来源定位与事实确认要分别记录。没有单独提取调用后，写作同次输出的主体/用途不能被当作独立事实证明。
2. 原文直接写章可能重新放大上下文。只传本章相关片段与必要条件、保留全文归档，长输入仍分批；重点章内容深度靠后续扩写而非一次堆满材料。
3. 章节修改依赖cards.json、extraction.json和factIds；新格式需兼容现有卡库与旧运行，不可只存正文。
4. 后台复核必须绑定章节/文档版本。先交稿不等于无版本约束地并发写文件；复核只追加检查结果，不覆盖用户的新正文。
5. 初稿可读时与后台检查中的状态要明确；人工定稿仍为单独动作，不能把未审内容说成全部通过。
6. 暂不继续提高八路并发。先用计时判断模型服务、限流或上下文瓶颈；模型路由是否能用低思考仍看提供方声明和真实指标。

## 本轮落地范围

1. 规划一次请求归纳宏观事实、粗目录和主线；最多四条选段，每条1800字符。完整原文留档，plan/SHA/确认和知识库真实命中门槛不变。
2. draft/standard每批同次归纳事实和写作，取消独立提取调用；原文卡映射为兼容旧章节修改的事实卡。长原文每窗2400、重叠160、每批最多8000字符，续写摘要最多八段；中断不将facts.text当正文。
3. 主查询一条；成功但为空或少于160非空白字符再补一条不同查询，失败不扩查；每章真实命中和规划锚点分别记录。
4. 首章即刷新report，全章产物已交后宿主任务继续关联必检，job/claim和取消恢复不提前结束；初稿可读、复核完成和通过分别记录。复核中仅list可读，改稿待结束或取消并释放锁。
