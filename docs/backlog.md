## 当前基线

- 独立 DSH 插件，材料转 Markdown、项目知识库同步、解析状态查询、授权库混合检索可用。
- `0.2.4` 已实现共享组稿规划，默认八条、可配置 1–12 条章节提取→撰写→校验流水线，失败局部重试与保存，按目录合稿后复核；四步定向取材已写入通用规则，自动调度仍待实现。
- 业务现状/需求挑战、PEST/管理业务技术各二选一；业务分析 15–30%、解决方案及子章 40–60% 为软目标。标题由 LLM 生成近义表达，章节 key/roleId 不变。
- 新流水线通过自动化测试；两类全景动态内容规则和合稿后单轮追加已实现，内容学习归入 P0；图片样式与渲染仍为 P3。此前浏览器真实报告来自 `0.1.7/0.1.8`，不能当作当前版本的内容质量验收。
- 新统一检索接口尚未接入；当前仍使用 `hybrid-search`。无独立业务前端、单章编辑工具、HTML/PPTX/PDF。

## 新接口对架构的影响

`POST /api/v1/knowledge-bases/{knowledge_base_id}/retrieval/query` 可一次返回 `hybrid`、`wiki`、`knowledge_graph`。它只检索，不负责生成、材料解析或训练。

| 来源 | 插件使用方式 | 证据边界 |
|---|---|---|
| hybrid | 正文取材与逐字引用 | 保存文档/chunk ID、位置、原文与来源信息 |
| wiki | 主题概览、补充线索、章节组织 | 保留页面 ID/版本及 source_refs/chunk_refs；派生总结不能冒充原始材料，关键事实尽可能回到原文 |
| knowledge_graph | 辅助发现实体关系，丰富能力→场景→问题关联候选 | 当前是知识库级图谱，不按查询文本筛选；不能直接视为客户事实、方案因果或全景架构图 |

接口按知识库调用，跨库仍由插件编排。`top_k/limit` 最大 100，未给分页协议，不能声称召回全库。`include_citations=true` 要显式请求；具体引用字段和可回取原文的接口仍需实测。

## 调度与文件边界

```text
src/platform.js       HTTP、认证与项目权限
src/retrieval.js      计划新增：查询、多来源归一化、来源覆盖与追溯
src/workflow.js       导入/检索/生成的阶段入口与运行状态
src/generation.js     共享规划、逐章提取撰写、合稿复核
src/panorama.js       当前单轮全景补充，保留原稿及覆盖核对
src/scheduler.js      当前进程内默认八路、可配置调度与取消
src/model.js          DSH 模型适配、共享请求额度与超时
src/content.js        引用与段落校验、可读报告
rules/templates/      方案类型默认结构
rules/chapters/       章节角色规则
rules/global.json     跨章组织、事实纪律与篇幅软目标
```

先固定同一版共享关联计划，再以默认最多八路逐章处理，最后检查前后对应。平台级持久任务、用户身份、目录版本与多人审批应复用后端已具备的能力；未核对接口前不自建另一套后台系统。

## 联调时必须核对，暂不阻断组稿

1. 文档过滤和标签过滤对 Wiki、图谱各自是否生效；当前文档仅明确图谱不按查询文本过滤，不能自行推定其文档范围。
2. Wiki 引用与图谱 chunks 如何回取原始正文，原始文档状态/权限变化时如何处理；已拿到的授权原文可先继续生成。
3. `partial=true` 的来源级失败及空图谱要分别展示；图谱 completed 且为空不是错误，不能补造关系。
4. 新响应错误在 `error.code/message`，定位信息在 `meta.trace_id`；当前旧适配器仅识别顶层 code 与响应头 request ID，需要补齐。
5. 统一检索不等于后台已完成 RAG/词对训练。解析、Wiki/图谱构建和可检索就绪状态仍需沿各自实际接口确认。
