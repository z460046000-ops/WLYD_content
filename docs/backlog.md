# 后续插件待办

更新：2026-10-16。依据产品计划、当前源码、统一检索说明及实际报告审阅。已实现与待验收分别列出，接口真实部署与内容质量仍以测试记录为准。

## 0.6.0 已实施与下一步

针对报告缺主干章、内部资料混入客户叙事、无案例却堆叠缺口说明的问题，已补五项控制：

1. 原有提取请求同时标注主体、用途、主题和候选身份，不新增串行分类；RAG 原料及所有召回原文保留。
2. 按有据能力组织场景、客户问题和趋势，过滤厂商内部问题和规划阶段话术；未知主体/用途在客户问题、趋势中保持候选，案例和企业介绍须取得明确用途。
3. 写前按主题去重、分批；无效段落有界局部修正，保留通过内容。失败批留下 partial 章，不把残稿标完整。
4. 只对明确可选且无适配正向内容的章节省略；必需或失败章节保留简短占位，目录仍支持自定义。
5. 正文与审核分开，新增 review.md/json；审阅按章去重且保留原始记录，status 返回审核路径及 partial/omitted 情况。

当前是源码调整；本轮未真实生成、未改知识库、未安装或重启日常 DSH。全局规则升到 0.8.0，需重新 plan/confirm，可以复用已有导入材料。140 项自动化及 21 模块语法检查通过；本地回归不能代替业务验收，详见测试记录。

接下来优先用同一批 CallWan 材料检查：用途分类是否准确、客户问题是否被候选正确标记、重点章能否完整展开、前后主线是否真实对应、可选案例省略是否符合预期。候选标签不构成披露许可；企业简介、真实客户需求和正式案例仍需按实际缺失补充。partial 恢复可复用提取，但本章写作重写；失败写作批独立恢复尚未实现。后续原文回读、身份映射、单章对话编辑及呈现导出计划不变。

## 历史：0.5.0 已实施与待验收

依据用户确认的《DSH最新代码耗时根因与优化方案-20261015.md》实施。本轮新增后台作业及时返回 runId、status/cancel、路由额度与两次有界429退避、分类错误处理、默认路由输出策略、持久去重和显式恢复、部分成稿状态、合稿关系合批与指纹缓存。规划确认与全段/全主线必检继续保留。

本版自动化汇总、打包 SHA-256 和安装结果以 [测试记录](test-record.md) 最终记录为准。没有真实模型生成，不将 Windows 他机报告或模拟测试耗时当成本机提速结果。

下一步按优先级：

1. **真实分阶段验收**：先规划与确认，再提交一次后台生成，按 runId 查询。核对实际 route/effort、输出策略、429尝试、输入规模、章节质量、来源和五项关联检查；不自动整篇重跑。
2. **取消与恢复验收**：已完成章可验证复用、权限撤回不复用越界证据、重启显式恢复、重复提交返回同运行、显式 regenerate 新建。作业只在 DSH 进程及会话生命周期内继续，不能关电脑仍运行。
3. **对话改单章**：当前 resume 处理未完成/失败部分，后续增加任意指定成功章的扩写、缩写和重写、前后差异及再次确认；变更后复查受影响关联。
4. **多来源与材料质量**：继续联调原文回读、Wiki/图谱、公开检索、OCR和大文件，校准goodcase方法与MVP章节规则。
5. **平台呈现和正式发布**：真实用户身份、文档不可变版本、多人确认，再接内容模型→HTML编辑→PPTX/PDF和正式CallWan安装。

仍需人工确认：词面/ID候选可能漏语义；自定义章节新角色需扩展跨章检查映射；补查数量不能证明缺项已解决；模型未声明低档时不能保证低思考生效。本机文件去重不是远程任务平台，旧版没有新版检查点的任务不可直接恢复。

以下基线和后端接入规划保留为历史背景；当前执行和模块以 README、architecture.md 为准。

## 当前基线

- 独立 DSH 插件，材料转 Markdown、项目知识库同步、解析状态查询、授权库混合检索可用。
- `0.3.0` 接通全局发现→共享规划→按章节取证→提取→最多一轮具体补查→撰写→校验；默认八条、可配置 1–12 条章节/模型流水线，后台检索另限四路，局部失败保存其余结果。
- 原始材料和命中证据完整存档，模型按阶段接收相关证据；知识证据有稳定 ID、查询归属与每章选择记录。本地使用词面与相邻段落选材，覆盖质量仍待真实材料验收。
- 运行固定实际会话模型路由，区分排队/执行超时与耗时，记录首事件/首文本及可得 token usage；尚不能据此宣称已获得特定提速比例。
- 业务现状/需求挑战、PEST/管理业务技术各二选一；业务分析 15–30%、解决方案及子章 40–60% 为软目标。标题由 LLM 生成近义表达，章节 key/roleId 不变。
- 两类全景动态内容规则和合稿后单轮追加已实现，内容学习归入 P0；图片样式与渲染仍为 P3。历史 `0.1.7/0.1.8/0.2.1` 浏览器报告不能当作当前版本的内容质量验收；最新验证见 [测试记录](test-record.md)。
- 新统一检索接口首期接 hybrid 原文，404/405 可明示回退旧 `hybrid-search`。Wiki/图谱、后台父块/邻块回读尚未接通；无独立业务前端、单章编辑工具、HTML/PPTX/PDF。

## 新接口对架构的影响

`POST /api/v1/knowledge-bases/{knowledge_base_id}/retrieval/query` 可一次返回 `hybrid`、`wiki`、`knowledge_graph`。它只检索，不负责生成、材料解析或训练。

| 来源 | 插件使用方式 | 证据边界 |
|---|---|---|
| hybrid | 已接适配：正文取材与逐字引用 | 保存文档/chunk ID、位置、原文与来源信息；真实过滤与部署仍需验收 |
| wiki | 待接：主题概览、补充线索、章节组织 | 保留页面 ID/版本及 source_refs/chunk_refs；派生总结不能冒充原始材料，关键事实应回到原文 |
| knowledge_graph | 待接：辅助发现实体关系，丰富能力→场景→问题关联候选 | 当前是知识库级图谱，不按查询文本筛选；不能直接视为客户事实、方案因果或全景架构图 |

接口按知识库调用，跨库仍由插件编排。`top_k/limit` 最大 100，未给分页协议，不能声称召回全库。`include_citations=true` 要显式请求；具体引用字段和可回取原文的接口仍需实测。

## 按优先级推进

| 顺序 | 任务与交付 | 影响模块 | 验收标准 |
|---|---|---|---|
| P0-1 | **先校准 MVP 章节规则**：选现有产品资料和完整 goodcase 做真实组稿，重点查业务分析、场景深度、问题与方案对应、受众和能力边界；只学习通用写法，不混入案例事实 | rules/、docs/mvp-rule-evidence.md、测试记录 | 逐章可追溯来源；同一问题在后文有对应方案；业务用户认可现状/挑战二选一和内容重点；比例不足只提醒 |
| P0-2 | **验收逐章取证与耗时**：固定材料、目录、受众、规则、实际模型/effort/并发做对照；核对全局发现、本地选段、跨章主线和补查成本 | retrieval.js、generation.js、model.js、测试记录 | 各章输入、全链路调用、排队/执行/重试成本分开报告；重点章节完整，必要材料不漏；规划降级/失败可见，不承诺固定提速比例 |
| P0-3 | **补齐后台原文回读与多来源**：先联调 hybrid 文档过滤、来源状态及回退，再确认父块/邻块读取，最后接 Wiki/图谱线索与原文回溯 | platform.js、retrieval.js、generation.js、content.js | 空结果、局部失败、401/403 与越界文档实测；Wiki/图谱范围未确认前不进入正文事实；一个场景串起真实能力证据、问题、趋势与方案 |
| P1-4 | **逐章对话修改**：扩写/缩写/重写指定成功章、定向补检索、展示前后差异；记录父版本、目录/证据/规则版本，修改后复核关联 | generation.js、workflow.js、index.js、新增版本存储模块 | 修改一章不重写无关章节；原版可恢复；失败不覆盖已确认内容；沿用0.5.0检查点和恢复边界 |
| P1-5 | **模板与确认体验**：售前模板实例支持增删换序与模式切换；接入用户提供的客户方案目录；展示逐章进度、来源、假设和待确认项 | templates/、工具参数、后续平台前端、后端目录/版本接口 | key/roleId 不因近义标题变化而改变；变更预览、确认、版本记录可追踪；缺关联不阻断生成，缺事实给候选或追问 |
| P2-6 | **补输入与检索兜底**：按需求接 OCR/扫描件、链接、其他文件；补公开检索与来源日期；核对 500 MB 真实链路及 DSH 用户身份映射 | convert.js、platform.js、外部检索适配器、平台身份契约 | 各格式明确已通/未通；无来源政策或数字不伪装成事实；用户隔离和大文件边界实测；DMG 解析策略单独确认 |
| P3-7 | **内容确认后再做呈现与发布**：全景内容规则已按用户图片与 PDF 落地；继续确认图形样式，定义内容模型→HTML→编辑→PPTX/PDF；最后适配 CallWan 打包规范与 skill | 新增呈现/导出适配器、插件发布配置 | HTML 可编辑；全景图语义与样式经确认；实际 PPTX/PDF 可打开且内容对应；通过正式平台安装验收 |

建议下一步：用现有 CallWan 材料复跑逐章取证，记录输入变化、各阶段耗时和重要材料遗漏，同时校准 MVP 规则。若仍有瓶颈，再依计时选择一个明确实验：降低特定阶段思考强度、8/6 并发比较或合并提取撰写；不同时改变多个因素。P1 以内容底座稳定为前提；不提前制作渲染模板。

## 调度与文件边界

```text
src/platform.js       HTTP、认证与项目权限
src/retrieval.js      授权文档准备、发现/按章查询、完整证据登记与选择、审计
src/tasks.js          宿主作业、及时返回runId、查询/取消/去重/显式恢复
src/persistence.js    原子检查点、接纳索引、运行占用与历史
src/workflow.js       导入/检索/生成的阶段入口与运行状态
src/generation.js     共享规划、逐章提取撰写、合稿复核
src/panorama.js       当前单轮全景补充，保留原稿及覆盖核对
src/scheduler.js      进程内全局默认八路、路由闸门与取消
src/model.js          固定路由、输出策略、429退避、独立排队/执行超时与用量
src/evidence-policy.js 同次提取的用途与主体规则、章节选材边界
src/content.js        引用与段落校验、正文与独立审核清单
rules/templates/      方案类型默认结构
rules/chapters/       章节角色规则
rules/global.json     跨章组织、事实纪律与篇幅软目标
```

先固定同一版共享关联计划，各章以稳定 key 取证并默认最多八路处理，最后检查前后对应。完整原文位于 evidence.json，根与每章 retrieval.json 记录取材过程。平台级持久任务、用户身份、目录版本与多人审批应复用后端已具备的能力；未核对接口前不自建另一套后台系统。

## 联调时必须核对，暂不阻断组稿

1. 文档过滤和标签过滤对 Wiki、图谱各自是否生效；当前文档仅明确图谱不按查询文本过滤，不能自行推定其文档范围。
2. Wiki 引用与图谱 chunks 如何回取原始正文，原始文档状态/权限变化时如何处理；已拿到的授权原文可先继续生成。
3. `partial=true` 的来源级失败及空图谱要分别展示；图谱 completed 且为空不是错误，不能补造关系。
4. 新接口的 `error.code/message`、`meta.trace_id`、来源状态及 404/405 回退记录需在真实部署核对；HTTP 200 不表示来源成功，401/403 不允许换旧接口绕过。
5. 统一检索不等于后台已完成 RAG/词对训练。解析、Wiki/图谱构建和可检索就绪状态仍需沿各自实际接口确认。
