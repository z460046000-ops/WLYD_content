# 文案与输出物分离：实施方案

日期：2026-10-16。状态：用户已确认，源码0.10.0已实施；本轮未安装插件、未重启DSH。保留设计依据，实际接口和验证见output-guide与test-record。上一批四项提速不重复实现。

## 1. 要解决的问题

1. 正文覆盖必须单独记录：九章都有节点或材料卡，不等于九章都有正文。外部0.8.0报告的七章needs_input原因没有原始日志，不能认定都是知识库缺料。
2. 先交可编辑的MD/DOCX，再基于相同文案版本提炼演示内容，输出可自由翻页HTML。当前只有MD/JSON，DOCX输出是新增能力。
3. 内容规则与版式规则分开，未来海报/视频增加输出适配器即可，不把视觉规则放回知识检索、章节提写与关联校验。
4. 会话编排避免为等待任务反复思考，状态包不反复进入模型上下文；有效规划可复用，调工具的会话可独立选择快模型。

## 2. 分层与文件

保留现有生成文件位置，逐步抽出边界，不为目录整齐搬动整套代码。

```text
rules/                          内容：取材、写法、事实边界、章节与关联
src/content/
  snapshot.js                   从report生成与输出格式无关的文案版本
  coverage.js                   正文覆盖、缺料与失败分类
src/outputs/
  registry.js                   输出适配器入口
  markdown.js                   MD视图
  docx.js                       DOCX视图
  html-slides/
    plan.js                     文案→关键点→精简演示稿
    render.js                   精简稿→HTML，加载本地幻灯片引擎
    validate.js                 内容映射、翻页、布局检查
src/delivery/
  tasks.js                      文档完成后提交独立HTML宿主作业
  manifest.js                   产物路径、源版本、生成状态与过期标识
prompts/outputs/
  presentation.md               只给演示改写阶段的提示词
vendor/xiaoma-studio/            固定上游commit、许可证及幻灯片所需资源
orchestration/                  DSH会话流程/状态摘要契约；不混入内容规则
```

文案快照包含标题、可变目录、章节/段落ID与版本、正文、引用、主线关系、能力边界、候选/待补及复核状态；不包含颜色、页型、动画或字体。先以report.json为主记录，新增稳定投影，不另建可并发改写的第二份正文。

每份输出记录sourceContentSha256、章节版本和renderer/skill版本。演示稿slides.json引用sourceBlockIds和主线编号，可精简、分页与调整顺序，不能新增业务事实或把候选写成已有。改文案后旧HTML标过期；只改主题时不重新检索或写整篇文案。

## 3. 默认流程

```text
知识库取材→粗大纲→用户确认→并行章节文案→关联必检
                                      ↓
                             保存确定版本的文案快照
                                      ↓
                             交付MD和DOCX及真实审核状态
                                      ↓
                             提炼关键点、精简演示文案
                                      ↓
                             xiaoma-studio HTML幻灯片
```

沿用0.9.0先交初稿能力，不把HTML耗时加回文案首次可读时间。文档产物发布后HTML另建宿主任务；HTML失败仍保留文档，支持只重试输出。无需为HTML重复确认原大纲；页面提纲可查看/修改，不增加新的强制审批。初稿或待确认内容生成的演示必须保留其审核身份，不能称已确认对外成稿。

DOCX/MD由同一快照确定性生成，不重新调用LLM撰写；HTML精简也读取该快照，而不反向解析DOCX。先使用原生Node文档依赖，浏览器与文档渲染仅用于开发验收；HTML运行不依赖Python、ffmpeg或视频音频模型。

## 4. 独立演示提示词

用户原意：

> 把这个解决方案，从中提取出关键点，然后精简文案，然后做成给客户展示的可自由翻页的HTML。

落地提示词：

> 基于已经交付的这一版本解决方案，提取面向客户的关键结论、业务问题、对应场景、解决做法和价值，精简为适合演示的短标题与要点，再使用xiaoma-studio制作可自由翻页的HTML幻灯片。一页围绕一个结论，保持“问题→场景方案→产品能力→相关趋势”的对应，保留适用条件、能力状态、待确认标记与来源映射。不新增客户、案例、数字、资质或承诺，不改动原始文案。内容过多时拆页，支持上一页/下一页、方向键、页码和全屏。

只进入输出阶段；具体主题、品牌色、字体、动效写在输出配置和skill中，不进入章节文字规则。HTML由结构化页面数据和固定引擎渲染，避免模型整页代码改写事实或注入无关行为。

## 5. 四项编排优化的核对

| 建议 | 当前事实与实施边界 |
|---|---|
| 不用代理轮询等待 | 当前wlyd_assembly_status只有run_id，没有阻塞等待参数；createTaskService查询即返回。优先在DSH宿主作业完成事件或前端轮询等待，变化时再唤起编排模型。是否有可接通知入口需检查目标DSH代码。不能假称现接口已有无限等待，也不以长时间sleep替代 |
| status只回摘要+差异 | 当前返回整份run状态，含modelRequests。若不改插件接口，必须由DSH工具结果适配层在送模型前摘取，单在提示词要求“忽略日志”仍会消耗上下文。摘要包括runId、阶段、正文覆盖/待补/失败、产物路径、短错误、revision；完整日志保留文件，按需取详情 |
| 规划缓存 | 已有确认planId可复用，输入和规则变化会拒绝。新自动缓存不能只以项目+受众+规则为键，还要作者/目标、模板/目录、材料、知识范围/版本、当前用户/权限及确认状态。先做显式已确认ID复用；缺可靠知识版本时不得无校验自动复用，也不能保证省九分钟或二次五分钟 |
| 编排模型快路由 | 仅调工具、展示状态与转交产物的会话选可配置快路由；章节写作/语义复核和演示精简模型分别配置，不随编排降级。模型是否可用与耗时取决于目标DSH路由，先验证配置和实际调用，不自行指定未知模型 |

这四项以会话/DSH适配层为边界，不改现有插件生成算法来假称会话开销已降低。若目标DSH缺必要入口，另列最小接口改动及影响后确认，不顺手改日常profile。缓存全面自动化和跨运行证据缓存仍独立于本次HTML输出。

## 6. 五步实施与验证

| 步骤 | 影响模块 | 如何验证 |
|---|---|---|
| 1. 正文覆盖与原因可见 | content/coverage、draft-generation、workflow；沿用真实知识库门槛 | 区分零命中、取材不适配、超时、无正文等；2正文7材料卡必须显示2/9正文；只对真实缺料给素材指引，保留可用段落与关系，不编造企业/案例 |
| 2. 文案快照与输出契约 | content/snapshot、outputs/registry、chapters | 同文案多格式共享来源和ID；换主题不发取材/写作请求；改一章后旧产物标过期，渲染不覆盖新正文 |
| 3. 先交MD/DOCX | outputs/markdown、docx、delivery/manifest | DOCX可打开，标题/引用/待确认身份与MD一致；渲染逐页看中文、分页和表格；产物实际落盘后才标就绪 |
| 4. HTML独立适配 | prompts/outputs、vendor、outputs/html-slides、delivery/tasks、官方输出工具 | 固定上游版本和MIT声明；确认精简稿只引用源段；离线打开、方向键/按钮/全屏/页码可用，逐页检查无溢出；HTML失败/取消不影响文档，不重新组稿 |
| 5. 编排接线与交付 | orchestration、目标DSH适配、README/architecture/backlog/test-record/memory及发版文件 | 验证等待不反复触发LLM、摘要在进入上下文前瘦身、有效plan复用/失效、路由隔离；跑最小回归、打包与SHA核验。未获后续指令前不安装或重启 |

## 7. 最容易出错与待人工确认

- 精简不能抹掉条件、能力状态、候选身份或问题方案关系；数字与结论始终映射原文段落，版式失败拆页而非随意删核心内容。
- 引擎和skill需要随插件在DSH里实际可用，不能只装到本机Codex后宣称插件已接入；选定资源真实加载与版本需要记录。
- 文案、机器审核、用户定稿与演示输出状态分别保存；不能把材料卡算成完整正文，不能把演示完成当内容验收通过。
- 渲染任务读取固定快照并独立写产物；用户改章时旧任务最多交付标过期产物，不修改文案或覆盖较新HTML。
- 当前缺外部0.8.0原始日志，七章缺正文根因仍待证实；当前没有本轮真实模型耗时；已增加合成DOCX/HTML样稿与离线检查，真实重点正文和演示观感仍需用户验收。
